# CLAUDE.md — «Цепочка»

Обучающий экономический симулятор для школ. Полный дизайн — в `docs/GDD.md`. Прочитай его перед первой задачей; формулы модели — раздел 5.

## Язык
- Документация, комментарии к дизайну, коммиты и общение — на русском.
- Код, идентификаторы, имена файлов — на английском.
- Все строки UI — только через `src/i18n/ru.json`, никаких захардкоженных строк.

## Стек
TypeScript (strict) · Vite · Preact · PixiJS v8 · uPlot · zod · Vitest · vite-plugin-pwa · GitHub Pages.
Версии пакетов фиксировать точно (без `^`). Новые зависимости — только с обоснованием в PROGRESS.md.

## GitHub и деплой
- Репозиторий: `Economy-learn`, основная ветка `main`.
- Сайт: `https://<username>.github.io/Economy-learn/`
- В `vite.config.ts` обязательно `base: '/Economy-learn/'`. Регистр букв важен: без этого на Pages будет белый экран.
- Пути к ассетам и JSON — только относительные или через `import.meta.env.BASE_URL`, никогда не с `/` от корня.
- Деплой: `.github/workflows/deploy.yml` — на каждый push в `main`: `npm ci` → `npm test` → `npm run build` → `actions/upload-pages-artifact` (папка `dist`) → `actions/deploy-pages`. Права в workflow: `contents: read`, `pages: write`, `id-token: write`. Если тесты красные — деплой не идёт.
- В Settings → Pages источник уже выставлен: GitHub Actions.
- Работа через ветки и PR: каждая задача в своей ветке, PR в `main` с кратким описанием на русском. Автоудаление веток включено.
- Если `docs/GDD.md` лежит в корне репозитория — перенеси его в `docs/` первым коммитом.

## Архитектура
```
src/
  sim/        чистая симуляция: без DOM, без UI, без Math.random
    state.ts      типы состояния мира
    step.ts       step(state, actions, rng) -> { state, causes }
    systems/      production, pricing, demand, labor, credit, expectations, fx, government, logistics
    delay.ts      DelayQueue для отложенных эффектов
    causes.ts     причинный журнал
    rng.ts        seeded RNG
  data/       загрузка JSON + zod-схемы
  game/       контроллер уровня, цели, звёзды, сохранения, коды сценария/результата
  render/     PixiJS-карта (только читает state)
  ui/         Preact-компоненты
  i18n/
```

## Жёсткие правила
1. `src/sim/` не импортирует ничего из `ui/`, `render/`, `game/`. Симуляция — чистая функция.
2. Вся случайность — через `rng.ts` с seed. `Math.random` и `Date.now` в `sim/` запрещены.
3. Ни одной магической константы в формулах: всё в `data/balance.json`.
4. Каждая формула пишет вклады в причинный журнал. Сумма вкладов в цену = цена (тест).
5. Изменил формулу → обнови раздел 5 GDD и добавь/обнови тест.
6. Никаких сетевых запросов, аналитики, cookies, рекламы, внешних шрифтов и CDN. Сохранения — только localStorage/IndexedDB (это требование школ).
7. Mobile-first: проверять на 360×640 и 1366×768.
8. Цвет никогда не единственный носитель смысла: дублировать формой или знаком.
9. Все игровые тексты нейтральны: вымышленная страна, никаких реальных стран, политиков, войн.

## Тесты
- `npm test` должен быть зелёным перед каждым коммитом.
- **Invariant:** деньги сохраняются (кроме явных кредита и эмиссии), запасы ≥ 0, выпуск ≤ мощности.
- **Golden:** уровень + seed + фиксированный набор действий → метрики в допуске. При намеренном изменении баланса обновлять golden осознанно, с записью в PROGRESS.md.
- **Направление эффектов:** рост ставки → спрос ниже через 2–4 хода; потолок ниже себестоимости → выпуск падает; рост цены топлива → ИЦП растёт. Эти тесты защищают «честность» модели.

## Балансировка без UI
`npm run sim -- --level 05 --seed 42 --policy passive --turns 24`
Печатает таблицу метрик по ходам (ИПЦ, безработица, цены, дефицит). Политики-боты: `passive`, `hawk` (резко поднимает ставку), `dove`, `ceiling` (ставит потолок цен). Используй для проверки, что уровень проходим и что у разных стратегий разные исходы.

## Рабочий процесс
- Разработка идёт из облачных сессий с телефона: проверять результат по ссылке GitHub Pages после push.
- Одна задача → один коммит с понятным сообщением на русском.
- В конце каждой сессии и после каждого этапа обновлять `PROGRESS.md`: что сделано, что дальше, известные проблемы, решения по балансу.
- В начале сессии: прочитать `PROGRESS.md`, затем нужный раздел GDD.
- Если формулировка в GDD противоречива — не угадывать молча: записать вопрос в PROGRESS.md в раздел «Вопросы к Андрею» и выбрать самый простой вариант.
