# «Цепочка» — Game Design Document v1.0

Обучающий экономический симулятор для школ и курсов.
Статус: pre-production. Дата: 2026-10-02.

---

## 1. Суть

**Одной фразой:** игрок управляет экономикой небольшой страны, строит инфраструктуру и дёргает рычаги политики, а потом видит, как его решения через месяцы превращаются в цены, дефицит, безработицу и инфляцию. И может ткнуть в любую цифру и узнать, *почему* она такая.

### Столпы дизайна
1. **Видно, а не написано.** Любая цифра раскрывается в причину: цена хлеба раскладывается на звенья цепочки, рост инфляции на источники.
2. **Последствия с задержкой.** Решение сейчас, эффект через 1–6 месяцев. Это главный источник и интереса, и обучения.
3. **Нет правильного ответа, есть компромиссы.** Инфляция vs занятость vs доверие vs бюджет. Победить можно разными путями.
4. **Уровень = урок.** Один уровень проходится за 20–35 минут, чтобы влезть в 45-минутный урок вместе с обсуждением.

### Чем НЕ является
- Не бизнес-тайкун про заработок денег.
- Не точная макромодель. Модель упрощённая, но качественно честная: направления эффектов и их порядок должны совпадать с учебником.
- Не мультиплеер (вне скоупа до v1.0).

## 2. Аудитория и условия использования

| Сегмент | Где | Как |
|---|---|---|
| 8–11 класс | обществознание, экономика | учитель на проекторе или ученики на своих устройствах |
| Колледжи, вузы | вводные курсы экономики | самостоятельная работа, домашние задания |
| Бизнес-тренинги | корпоративное обучение | групповой разбор сценариев |
| Самообразование | дома | кампания и песочница |

### Жёсткие требования (из-за школ)
- Работает в браузере **без установки и регистрации**.
- Работает **офлайн** после первой загрузки (PWA): школьный интернет ненадёжен.
- **Никаких персональных данных, аналитики, cookies, рекламы, сетевых запросов.** Всё хранится локально на устройстве.
- Тянет **слабое железо**: старый школьный ноутбук, бюджетный планшет, телефон.
- Русский язык, но все строки вынесены в i18n.
- **Политическая нейтральность:** вымышленная страна «Республика», вымышленная валюта «колос» (кол.), никаких реальных стран, партий, войн. Шоки называются нейтрально: «внешний шок», «торговые ограничения», «неурожай», «авария на НПЗ».

## 3. Роль игрока (гибрид)

Игрок — **глава экономического блока** небольшой страны «Республика» из 3 провинций.

### Две руки игрока
**1. Строитель (государственная инфраструктура)**
- Дороги и их полосы (пропускная способность логистики)
- Склады / госрезерв (буфер на случай шока)
- Элеватор (хранение зерна)
- Электростанция / НПЗ (внутреннее топливо)
- Таможенный терминал (пропускная способность импорта)
- Госпредприятие (в крайнем случае: дорого и неэффективно, но спасает от дефицита)

**2. Регулятор (рычаги политики)**
- Ключевая ставка (Центробанк)
- Налоги: налог на продажи, налог на прибыль, налог на доходы
- Субсидии: адресные по товару или по звену цепочки
- Пошлины на импорт / экспорт
- Потолок цен
- Интервенции из госрезерва
- Валютные интервенции
- Госзакупки и трансферты населению
- Эмиссия (только в песочнице и финальных уровнях: удар по доверию)

### Кто производит
**Частный бизнес — это ИИ.** Фермы, мельницы, пекарни, грузовые компании сами открываются, расширяются и закрываются по прибыльности и стоимости кредита. Игрок не может приказать фермеру сеять: он меняет условия, а рынок отвечает.

Это и есть ключевой урок: государство не печёт хлеб, оно меняет правила игры.

### Исключение: микро-уровни
На уровнях 1–2 игрок — **владелец одной пекарни**, чтобы на своей шкуре понять себестоимость, цену и спрос. С уровня 3 он переходит на уровень страны, и его пекарня становится одной из ИИ-фирм.

## 4. Игровой цикл

**Ход = 1 месяц.** Уровень длится 12–36 ходов.

```
Брифинг / новости месяца
        ↓
Решения: стройка + рычаги (в любом порядке, можно отменить до конца хода)
        ↓
[Следующий месяц]  или  [Перемотать 3 месяца]
        ↓
Симуляция (мгновенно)
        ↓
Анимация потоков на карте (2–4 сек, можно пропустить)
        ↓
Сводка: что изменилось и почему (3–5 главных изменений с причинами)
        ↓
Проверка целей уровня
```

- Решения вступают в силу с задержкой (см. 5.12). Отложенные эффекты видны в UI как «в пути» (иконка с таймером): игрок должен понимать, что ставку он уже поднял и результат ещё не пришёл.
- Ошибки не смертельны: проигрыш наступает только при катастрофе (доверие = 0, голод, дефолт). Иначе уровень заканчивается в срок с 0–3 звёздами.

## 5. Экономическая модель

Тип модели: **stock-flow с задержками**, агрегированная по провинциям. Не агентная симуляция: детерминированность и балансируемость важнее реализма.

Все числа ниже — стартовые плейсхолдеры. Живут в `data/balance.json`, балансируются headless-прогонами.

### 5.1 Сущности
| Сущность | Кол-во | Что хранит |
|---|---|---|
| Province | 3 | население, рабочая сила, домохозяйства (агрегат), здания |
| Firm | 0..N на провинцию | тип, мощность, запасы входов/выхода, долг, цена, наценка, занятые |
| Households | 1 агрегат на провинцию | доход, сбережения, долг, потребительская корзина, ожидания |
| Bank | 1 | ключевая ставка, спред, объём кредитов |
| Government | 1 | бюджет, долг, налоги, субсидии, резервы |
| World | 1 | мировые цены, внешняя ставка, спрос на экспорт |
| Route | рёбра графа | пропускная способность, стоимость перевозки |

### 5.2 Товары и рецепты

**MVP:** зерно, мука, хлеб, топливо. **v0.2:** + импортный товар «техника».

| Производитель | Выход (1 ед.) | Входы |
|---|---|---|
| Ферма | зерно | топливо 0.10, труд 0.20 |
| Мельница | мука 0.8 | зерно 1.0, топливо 0.05, труд 0.10 |
| Пекарня | хлеб 1.0 | мука 0.5, топливо 0.05, труд 0.30 |
| НПЗ | топливо 1.0 | труд 0.20 (мощность ограничена) |
| Импорт топлива | топливо | мировая цена × курс × (1 + пошлина) |
| Импорт техники | техника | мировая цена × курс × (1 + пошлина) |

**Логистика:** перевозка 1 ед. по ребру стоит `топливо 0.02 × длина + труд 0.01`. Пропускная способность ребра ограничена: при её превышении товар ждёт в очереди (узкое место).

**Топливо — сквозной ресурс.** Оно входит во все звенья и в логистику. Это нужно, чтобы показать инфляцию издержек.

**Энергия (v0.2).** Отдельный товар, его производит электростанция (отдельное здание, не НПЗ): на 1 ед. энергии — топливо 0.3, труд 0.1. Энергию потребляют все здания (входит в рецепты и себестоимость) и домохозяйства. В ИПЦ энергия **не входит**. Позже — отдельные показатели сектора «Энергетика», нагрузки энергозатрат на бизнес и население; ещё позже — возможно, индекс стоимости жизни, куда энергия войдёт.

### 5.3 Производство
```
план_выпуска = ожидаемые_продажи × (1 + k × (целевое_покрытие − текущее_покрытие))
выпуск = min(мощность, план_выпуска, доступные_входы, доступный_труд, деньги_на_входы_и_зарплату) × модификатор_шока
```
- `модификатор_шока` — произведение множителей мощности действующих шоков (`data/shocks.json`): шок урезает доступную мощность зданий своего типа (по стране или в провинции) на `turns` ходов. MVP: «неурожай» (фермы ×0.5, 3 хода), «авария на НПЗ» (НПЗ ×0.4, 2 хода).
- `ожидаемые_продажи` — средние **заказы** за `salesAverageTurns` ходов. Заказы = продажи + доля неудовлетворённого спроса на товар (делится между производителями пропорционально мощности). Так фирма видит спрос, даже когда ей нечего продать.
- `покрытие = запас / ожидаемые_продажи`, не больше `coverageCap`.
- `k` (`inventoryAdjustSpeed`) — какую долю разрыва в запасах фирма закрывает за ход. При k = 1 цепочка из четырёх звеньев раскачивается («эффект хлыста»): безработица колеблется от 0 до 30%. Поэтому k < 1.
- Если труда на все планы не хватает, все планы — и фабрик, и перевозчика (по его занятости прошлого хода) — урезаются в одной пропорции. Иначе при перегретом рынке труда перевозки встают первыми и останавливают всю цепочку.

### 5.4 Ценообразование (себестоимость + наценка)
```
себестоимость c = Σ(вход_i × цена_i) + зарплата × труд + логистика + налоги
покрытие cov = запас / средние_продажи_за_3_мес
наценка m(t+1) = clamp(m + β × (cov_target − cov) / cov_target, m_min, m_max)
целевая_цена P* = c × (1 + m)
цена P(t+1) = P + α × (P* − P) + P × π_e × γ
```
- α ≈ 0.3–0.5 — липкость цен
- γ — доля ожидаемой инфляции, которую фирмы закладывают заранее
- Себестоимость считается на единицу выхода: входы — по средней цене сделок за ход, `c_k = вход_k × P_k / выход`.
- Налог с продаж τ платит продавец с каждой продажи (оборотный налог, есть в каждом звене). Он закладывается в цену: `P* = c × (1 + m) / (1 − τ)`, компонента `tax.sales` = τ × P*.
- Субсидия σ — доплата государства производителю за каждую проданную единицу товара. С ней `P* = (c × (1 + m) − σ) / (1 − τ)`, компонента `subsidy` = −σ (отрицательная). σ ограничена `c × (1 + m)`, чтобы цена не уходила в минус. Объявленная субсидия доходит до производителей с лагом «Субсидия → цена» (5.12).
- Формула **аддитивная**, поэтому изменение цены точно раскладывается на вклады: входы, зарплата, логистика, налоги, наценка, ожидания. Это основа «Рентгена товара».
- Цена хранится как сумма компонент, и каждая компонента обновляется той же формулой:
  ```
  comp_k(t+1)       = (1 − α) × comp_k(t) + α × c_k          // input.<товар>, wage
  markup(t+1)       = (1 − α) × markup(t) + α × c × m(t+1)
  subsidy(t+1)      = (1 − α) × subsidy(t) − α × σ
  tax.sales(t+1)    = (1 − α) × tax.sales(t) + α × τ × P*
  expectations(t+1) = (1 − α) × expectations(t) + γ × π_e × P(t)
  ```
  Σ компонент = P(t+1) точно (тест). Рыночная цена товара — средняя цена сделок за ход, её разложение — среднее разложений продавцов, взвешенное по продажам.

### 5.5 Спрос домохозяйств
```
бюджет B = зарплаты + трансферты − налоги − обслуживание_долга + новый_кредит
доля_трат s = s0 − k_r × (ставка − нейтральная_ставка)    // высокая ставка → сберегают
Q_i = base_i × N × (P_i / P_ref_i)^ε_i × (B×s / N / B_ref)^η_i
```
- `B` в MVP — деньги домохозяйств на момент покупок: сбережения + зарплата за этот ход (за вычетом налога) + дивиденды и трансферты прошлого хода + новый кредит − обслуживание долга. Траты за ход — `s × B`, остальное — сбережения.
- **Потребительский кредит:** желаемый долг = `max(0, d0 − k_d × (ставка − нейтральная)) × доход прошлого хода`; за ход население закрывает долю `householdDebtAdjustSpeed` разрыва: берёт кредит или гасит (не больше своих денег). Проценты — банку (нечем — в долг). Ставка для населения — ставка спроса (догоняет ключевую с лагом «ставка → спрос») + спред. Высокая ставка бьёт по спросу двумя путями: население больше сберегает (s) и гасит кредиты.
- `P_ref_i` — стартовая цена товара на уровне, `B_ref` — стартовые траты на душу. На старте Q_i = base_i × N.
- Ставка в формуле `s` — не объявленная ключевая, а ставка, на которую домохозяйства уже отреагировали (догоняет ключевую с лагом из 5.12).
| Товар | ε (цена) | η (доход) | Характер |
|---|---|---|---|
| Хлеб | −0.2 | 0.3 | необходимость, есть минимум потребления |
| Техника | −1.5 | 1.5 | роскошь, легко откладывается |

После расчёта спрос нормализуется к бюджету: если корзина дороже `s × B`, сначала оплачивается минимум потребления (`minShareOfBase × base_i × N`), остальное урезается пропорционально; если дешевле — разница сберегается. Если предложение < спроса — **дефицит**: неудовлетворённый спрос показывается очередями и пустыми полками.

### 5.6 Потолок цен и чёрный рынок
- Если потолок < себестоимости — фирма сокращает выпуск (до закрытия).
- Неудовлетворённый спрос частично уходит на чёрный рынок по цене `P_bm = P_ceiling × (1 + k × дефицит)`.
- В ИПЦ попадает средневзвешенная официальной и чёрной цены. Именно так игрок видит, что потолок «не сработал».

Реализация (MVP):
- Потолок — рычаг по товару, действует сразу на все продажи производителей во всех провинциях. Цена фирмы = min(расчётная, потолок); срез — отрицательная компонента `priceCeiling` в разложении. Расчётная цена под потолком продолжает считаться по 5.4, поэтому после снятия потолка цена возвращается к ней.
- Любой убыток на единицу (цена после налога + субсидия < себестоимости) режет выпуск: план × `(1 − lossOutputCut × (c − выручка) / c)`; если убыток держится `closeAfterLossTurns` месяцев — фирма закрывается (5.8).
- Чёрный рынок: перед потребительским рынком фирма придерживает долю склада `blackMarketShareOfUnmet × дефицит прошлого хода в её провинции`. После официального рынка население докупает `blackMarketShareOfUnmet × неудовлетворённый спрос` у придержавших по `P_bm = потолок × (1 + k × дефицит)` в пределах своих денег. Налога нет, премия к официальной цене — компонента `blackMarket`. Непроданное возвращается на склад.
- Дефицит появляется не сразу: сначала его гасят запасы (лаг «потолок → дефицит» 1–3 мес возникает сам).

### 5.7 Труд и зарплаты
```
безработица u = 1 − занятые / рабочая_сила
зарплата w(t+1) = w × (1 + φ × (u* − u) + π_e)
```
Низкая безработица + высокие ожидания = спираль «зарплаты → цены → зарплаты». Она возникает сама, её не надо скриптовать.

Зарплаты «липкие» вниз: номинальная зарплата падает не быстрее `maxMonthlyWageCut` в месяц (в журнале — вклад `labor.stickyWages`). Без этого при массовой безработице зарплаты и цены проваливаются в дефляционную спираль: у населения копятся деньги, которые нечего купить, оно выкупает всё топливо, и цепочка встаёт.

### 5.8 Кредит и инвестиции
```
ставка_кредита = ключевая + спред
фирма расширяется, если ожидаемая_ROI > ставка_кредита + порог
стройка новой мощности: 3–6 месяцев (задержка)
новые фирмы появляются, если в провинции устойчивый дефицит и высокая маржа
фирмы закрываются после N месяцев убытков
```
Реализация (MVP):
- Ставка кредита = ставка кредитования (догоняет ключевую с лагом 5.12) + `loanSpread`.
- **Оборотный кредит:** если на план не хватает денег, а продавать выгодно (цена после налога выше себестоимости), фирма занимает недостающее; долг ≤ `maxDebtToMonthlySales` × ожидаемые продажи за месяц.
- Проценты платятся банку каждый ход; если нечем — добавляются к долгу. Деньги сверх буфера сначала гасят долг, потом идут в дивиденды.
- **Вход:** новая частная фирма строится в провинции, если там `entryShortageTurns` ходов подряд дефицит товара больше `entryShortageThreshold`, средняя наценка производителей ≥ `entryMinMarkup`, их загрузка ≥ `entryMinUtilization` (дефицит из-за мощностей, а не из-за нехватки входов), и годовая окупаемость `12 × прибыль при полной загрузке / стоимость стройки` > ставка кредита + `expansionRoiMargin`. Стройка — в кредит на всю стоимость, мощность появляется через `buildTurns`; пока идёт стройка, убытки не считаются.
- **Выход:** частная фирма после `closeAfterLossTurns` месяцев убытков подряд закрывается: деньги гасят долг, остаток долга банк списывает, остаток денег — владельцам. Госфирмы не закрываются.

### 5.9 Ожидания и доверие
```
адаптивные: π_a(t+1) = λ × π_a + (1 − λ) × π_факт
ожидания: π_e = C × π_цель + (1 − C) × π_a
```
**Доверие к ЦБ C ∈ [0, 1]:**
- растёт, когда инфляция близка к цели;
- падает от резких разворотов политики, потолков цен, эмиссии, невыполненных обещаний.

### 5.10 Курс валюты
```
e(t+1) = e × (1 + κ × (−торговый_баланс / ВВП) − μ × (ставка − мировая_ставка) + шок)
```
Курс влияет на цену импорта с переносом 1 месяц. Это импортная инфляция.

### 5.11 Государство
- **Доходы:** налоги, пошлины.
- **Расходы:** стройка, субсидии, трансферты, закупки в резерв, обслуживание долга.
- **Дефицит бюджета** покрывается займом (растёт долг и премия к ставке) или эмиссией (только в разрешённых уровнях: удар по доверию и рост денег у населения → инфляция спроса).

Реализация (MVP):
- Налоги: с продаж τ_s (платит продавец с выручки, в цене — 5.4), на прибыль τ_p (с положительной прибыли фирмы за ход), на доходы τ_i (удерживается из зарплат, в т. ч. перевозчика). Ставки — рычаги игрока, старт — из уровня.
- Доходы госфирм (НПЗ) — их дивиденды — идут в бюджет.
- Субсидии по товару — рычаг: σ за единицу, платится производителю при каждой продаже (5.4).
- Трансферты — рычаг: сумма на душу в месяц. Уровень может задать `"balanced"`: трансферты, при которых стартовый бюджет сбалансирован.
- Стройка оплачивается в момент решения; деньги уходят строителям — населению.
- Проценты по долгу: `ставка = ключевая (дошедшая до кредитов) + debtRatePremium × долг / годовой ВВП`, платятся держателям облигаций (население) и банку; банк отдаёт доходы владельцам — населению.
- В конце хода минус на счёте закрывается **займом**: население покупает облигации на свои деньги (пропорционально деньгам провинций). Займ не создаёт денег — он перекладывает сбережения в бюджет (облигации не тратятся на покупки). Только если денег у населения не хватает, остаток выкупает банк — тогда деньги создаются. Профицит гасит сначала долг банку, потом облигации (деньги возвращаются держателям). **Эмиссия** (создание денег) — отдельный рычаг песочницы и финальных уровней (позже).
- Почему так: при займе в банке любой дефицит превращался в новые деньги, и рецессия после повышения ставки сама переходила в бум (дефицит 4% ВВП в месяц). Получалось, что высокая ставка через 2 года даёт инфляцию выше, чем без неё, — неверный урок.
- Сальдо бюджета раскладывается по статьям в причинном журнале (`budget.balance`).

**Госрезерв (MVP):**
- Склады строит игрок в провинции: склад (любые товары) и элеватор (только зерно); стоимость — из бюджета, готовность — через `buildTurns`. Уровень может задать склады и запасы на старте.
- Место делится «узкие первыми»: товар сначала занимает склады, которые хранят меньше видов товаров (зерно — в элеватор), универсальные склады — остальное.
- **Закупка в резерв:** государство — покупатель на потребительском рынке провинции, не больше свободного места; расходы — статья `reserve`.
- **Интервенция:** резерв продаёт на местном рынке своей провинции (и фабрикам, и населению) по текущей цене провинции, но не выше потолка; доходы — статья `reserveSales`, в разложении цены — компонента `reserve`. Непроданное остаётся в резерве. Резерв не возит товар между провинциями.

### 5.13 Показатели
| Показатель | Как считается |
|---|---|
| ИПЦ (CPI) | корзина: хлеб 0.35, мука 0.10, топливо 0.25, техника 0.30 (MVP без техники — перенормировать). `ИПЦ = 100 × Σ w·P / Σ w·P_ref`; вклад товара в изменение = `100 × w × ΔP / Σ w·P_ref` |
| ИЦП (PPI) | цены производителей по звеньям: цена производителей товара — средняя цена фирм, взвешенная по выпуску; `ИЦП = 100 × Σ w·Pp / Σ w·Pp_ref`, веса — доли товаров в стартовом выпуске по стоимости; вклад товара в изменение раскладывается так же, как в ИПЦ |
| Инфляция | м/м и г/г (по 12 ходам) |
| Безработица | 5.7 |
| ВВП | сумма добавленной стоимости: выручка фирм − покупка входов + выручка перевозчика − его топливо |
| Реальная зарплата | зарплата / ИПЦ |
| Торговый баланс | экспорт − импорт |
| Госдолг | накопленный дефицит |
| Доверие к ЦБ | 5.9 |
| Социальное доверие | от реальных доходов, дефицита, безработицы; 0 = проигрыш |

### 5.14 Детерминизм
- Вся случайность только через seeded RNG.
- Одинаковые seed + действия = одинаковый результат. Это нужно для:
  - режима учителя (весь класс играет один и тот же сценарий);
  - сравнения прогонов («что если»);
  - golden-тестов.

### 5.15 Инварианты (проверяются тестами)
- Деньги не появляются из ниоткуда, кроме явной эмиссии и кредита: сохраняется `Σ денег − Σ долгов + списанные долги`.
- Запасы ≥ 0.
- Выпуск ≤ мощности.
- Сумма вкладов в «Рентгене» = итоговая цена (с точностью до округления).

### 5.16 Рынок, деньги и порядок хода (MVP)
**Рынок товара** (свой в каждой провинции; как товар попадает между провинциями — 5.17):
- Продажи делятся между продавцами пропорционально их запасу: все продают одну и ту же долю склада. Ценовая конкуренция между фирмами — в v0.2 (уровень «Конкурент»).
- При нехватке все покупатели получают одну и ту же долю заявки; неудовлетворённая часть — дефицит и сигнал заказов для фирм.
- Каждый платит среднюю цену предложения, но не больше своего бюджета. Σ оплат = Σ выручки.

**Деньги** живут на счетах домохозяйств, фирм и государства и только переходят между ними:
- Фирмы платят зарплату (домохозяйствам пропорционально рабочей силе) и покупают входы у звеньев выше по цепочке.
- Фирма держит на счёте буфер `cashBufferTurns` месяцев ожидаемых издержек; избыток × `dividendPayoutShare` — дивиденды: частных фирм — домохозяйствам пропорционально населению, государственных — в бюджет.
- До M5 (бюджет и рычаги) государство сразу возвращает все доходы населению трансфертами пропорционально населению.

**Порядок хода:** решения игрока и созревшие эффекты → планы фирм (урезка по труду и деньгам) → перевозчик докупает топливо → рынок входов (местное, затем привозное) → производство и зарплаты → потребительский рынок (местное, затем привозное) → заказы, цены провинций и страны, прибыль, дивиденды → новые наценки и цены → ИПЦ → зарплата → ожидания.

**Цены по провинциям.** Цена товара в провинции — средняя цена сделок в ней за ход, с доставкой. Цена по стране — средняя по провинциям, взвешенная по населению; она идёт в ИПЦ. Фирма считает себестоимость по ценам входов в своей провинции. Домохозяйства сравнивают цену своей провинции с её стартовой ценой (P_ref провинции), а свои траты — со стартовыми тратами провинции (B_ref).

### 5.17 Логистика
**Граф.** Узлы — провинции, рёбра — дороги: длина и число полос. Дорога с 0 полос нарисована на карте, но не проезжая: её можно достроить. Пропускная способность дороги = полосы × `capacityPerLane` за ход **в каждую сторону** (встречные потоки друг другу не мешают). Товар идёт по кратчайшему (по длине) пути через проезжие дороги.

**Перевозчики** — частный (ИИ, как фирмы) и государственный (строит игрок):
- у каждого **автопарк**: единицы `truckFleet`, каждая даёт `workCapacity` работы (груз × длина) за ход;
- перевозку берёт сначала тот, у кого тариф ниже (госпарк — без наценки), в пределах парка и топлива; остальное — частный. Цена доставки — средневзвешенный тариф перевозчиков этой перевозки;
- перед рынком входов перевозчики докупают топливо у всех НПЗ страны: ожидаемая работа всех перевозчиков делится между ними в том же порядке в пределах парка, цель запаса = доля × `fuelPerUnitLength` × (1 + целевое покрытие);
- на каждую единицу груза тратится топливо `fuelPerUnitLength × длина пути` и труд `laborPerUnit × число рёбер`, перевозчик платит зарплату;
- тариф `(топливо × цена топлива + труд × зарплата) × (1 + наценка)`: у частного `markup`, у госпарка 0;
- **частный** платит проценты, гасит долг, излишек денег — дивиденды населению; если загрузка парка (с учётом работы, на которую парка не хватило) ≥ `entryMinUtilization` и окупаемость единицы выше ставки кредита + `expansionRoiMargin` — заказывает +1 единицу в кредит (по одной за раз, готова через `buildTurns`);
- **госпарк** строит игрок за деньги бюджета; итог хода госперевозчика (выручка − топливо − зарплата) уходит в бюджет или покрывается из него (статья `stateCarrier`). Рычаг на случай, когда частный парк — узкое место.

**Как товар попадает между провинциями.** На каждом рынке (входов и потребительском):
1. покупатели берут местное (5.16);
2. нехватка провинции p делится между провинциями с остатками, достижимыми из p, пропорционально остаткам;
3. если у источника просят больше, чем есть, — заявки урезаются пропорционально;
4. если по дороге в каком-то направлении хотят провезти больше её остатка — урезаются **все** перевозки через неё в этом направлении, всех товаров одинаково; не влезшее остаётся у продавцов и показывается как «очередь» этой дороги в этом направлении (узкое место);
5. если у перевозчика не хватает топлива или свободного труда — урезаются все перевозки;
6. покупатели в p платят за привозное `средняя цена продавцов источника + тариф`; в разложении цены тариф — компонента `logistics`.

Пропускная способность каждого направления дороги за ход делится между рынком входов и потребительским пропорционально заявкам на перевозку прошлого хода: рынок входов получает свою долю, потребительский — всё, что осталось. Так в пробке страдают все понемногу, а не только тот, кто торгует позже.

**Логистика в себестоимости.** Если в цене входа сидит логистика (доставка или логистика звеньев выше по цепочке), она попадает в себестоимость отдельной компонентой `logistics`, а не внутрь `input.<товар>`. Поэтому «Рентген» хлеба показывает всю логистику цепочки одной строкой.

**Стройка полосы** — действие игрока: +1 полоса через `buildTurns` ходов (5.12). Оплата из бюджета — с M5.

## 6. Причинный журнал (Cause Graph) — ключевая фича

Каждое значимое изменение записывается с причинами и их долями.

```ts
interface CauseEvent {
  id: string;
  turn: number;
  metric: string;          // "price.bread.province1", "cpi", "unemployment"
  delta: number;
  causes: { ref: string; share: number; label: string }[];
}
```

Используется в трёх местах:
1. **«Рентген товара»** — тап по хлебу: столбец «из чего состоит цена» + цепочка звеньев с вкладом каждого + что изменилось за месяц.
2. **Кнопка «Почему?»** у любой цифры — 2–3 главные причины простым языком.
3. **Отчёт уровня** — цепочка причин от решения игрока до итога:
   > Вы ввели потолок цен на хлеб → пекарни ушли в убыток → выпуск −30% → дефицит → чёрный рынок +45% → инфляция выросла на 2.1 п.п.

Тексты генерируются по шаблонам из `data/explanations.json`.

Реализация (MVP):
- Симуляция пишет события без текста: `{ id, turn, metric, delta, causes: [{ ref, value, share }] }`, Σ value = delta (тест). Текст (`label`) строится в UI по шаблонам, а не хранится в состоянии.
- События каждого хода: цены фирм (`price.firm.<id>`), цены в провинциях (`price.<товар>.<провинция>`) и по стране (`price.<товар>`) — по компонентам цены; `cpi` и `ppi` — по товарам; `wage` — разрыв безработицы, ожидания, липкость; `unemployment` — по отраслям (вклад = −Δзанятых в отрасли / рабочая сила); `budget.balance` — по статьям бюджета.
- `data/explanations.json`: группы (цена, ИПЦ, ИЦП, зарплата, безработица, бюджет). В группе — шаблоны метрик и причин (`input.{good}`, `employment.{sector}`) и ключи `ru.json` для роста (`up`) и падения (`down`). Одна и та же причина (например, `tax.sales`) в разных группах объясняется по-разному.
- «Почему?» — 2–3 причины с наибольшим вкладом: «▲ Подорожал вход «Мука» — 62%». Стрелка дублирует цвет.
- Сводка за период — сумма вкладов одинаковых причин за несколько ходов (для отчёта уровня, M10).
- Тест: прогон со всеми рычагами и шоками — у каждой метрики и причины в журнале есть шаблон, тексты подставлены полностью.

## 7. Визуал и UI

### Стиль
Абстрактный, в духе Mini Metro: всё рисуется процедурно, **без нарисованных ассетов**.
- Провинции — мягкие полигоны.
- Здания — геометрические фигуры: круг — ферма, квадрат — мельница, шестиугольник — пекарня, ромб — НПЗ, треугольник — склад, перевёрнутый треугольник — элеватор.
- Маршруты — линии с бегущими точками: плотность точек = объём потока, цвет = изменение цены (зелёный дешевеет, красный дорожает).
- Тепловая карта дефицита поверх провинций.
- **Доступность:** цвет всегда дублируется формой или знаком (▲▼), палитра безопасна для дальтоников.

Реализация карты (MVP, M7):
- Раскладка — в уровне/сценарии (`map`): виртуальные координаты, у провинции контур (рисуется сглаженным), центр (здания и подписи) и узел дорог `hub` (дороги приходят в узлы и не перекрывают здания); у дороги — необязательные изгибы `via`. Рендер вписывает раскладку в экран.
- Тепловая карта: заливка провинции по наибольшему дефициту у населения — 4 уровня (< 5%, 5–20%, 20–50%, ≥ 50%), последовательная шкала по светлоте; знак «!», «!!», «!!!» у названия дублирует цвет.
- Тренд цен провинции за ход: ▲ / ▼ у названия. Точки на дорогах: цвет — тренд цен в провинции назначения. Вместо зелёного/красного — синий (дешевеет) и оранжевый (дорожает): эта пара различима при дальтонизме; смысл всё равно дублирует ▲ / ▼.
- Здания: одна фигура на тип в провинции с числом «×5»; строящиеся — контуром («3+1» — готово + строится). Склады резерва — треугольники коричневым.
- Дороги: толщина — число полос, пунктир — 0 полос (можно построить); узкое место (очередь в любом направлении) — красный круг со знаком «!» в середине дороги.
- Потоки: точки на направление пропорциональны грузу (1 точка на 25 ед., не больше 16), встречные потоки идут по разным сторонам дороги.
- Подписи — на светлой подложке и не масштабируются вместе с картой (читаются на телефоне).

### Экраны
1. Главное меню
2. Карта кампании (12 уровней)
3. Брифинг уровня: ситуация, цель, новые механики
4. **Основной экран**
   - сверху: ИПЦ, безработица, бюджет, доверие (тап → график)
   - центр: карта
   - снизу: панель «Строить» / «Политика» / «Графики»
   - кнопка хода
5. Рентген товара
6. Графики: ИПЦ, ИЦП, безработица, ВВП, ставка, курс, бюджет. Можно наложить два прогона.
7. Сводка месяца
8. Отчёт уровня: звёзды, причинная цепочка, вопросы для обсуждения, «переиграть с другим решением»
9. Песочница: настройки
10. Режим учителя
11. Глоссарий

Реализация основного экрана (MVP, M8):
- Верхняя панель: ИПЦ (▲▼ за месяц), безработица, сальдо бюджета и долг, доверие. Нажатие — «Почему?»: главные причины изменения за последний месяц из журнала.
- Панели «Политика» (ставка, налоги, трансферты, субсидии, потолки цен, госрезерв) и «Строить» (полосы дорог, склады и элеваторы, госпарк) — с ценой и сроком стройки. Изменение рычага становится решением месяца; решения можно отменить до хода; повторное решение по тому же рычагу заменяет прежнее, возврат к текущему значению — отменяет.
- «В пути»: отложенные эффекты (ставка → кредит/спрос, субсидии, стройки, новые фирмы) с числом месяцев до эффекта.
- Ход: «Следующий месяц» или «Перемотать 3 месяца» → сводка месяца: 3–5 самых заметных изменений (ИПЦ, безработица, цены, зарплата, бюджет, дефицит ≥ 5% в провинции, новые и закрытые фирмы) с 2 главными причинами у каждого.
- На телефоне панели свёрнуты (видны вкладки и кнопки хода), чтобы карте хватало места; на компьютере (≥ 900 px) — колонка справа.

Реализация «Рентгена» и графиков (MVP, M9):
- «Рентген товара» (вкладка «Графики»): товар и рынок (вся страна или провинция). Полоса «из чего состоит цена» по группам: сырьё, зарплаты, топливо, доставка, наценка, налоги, ожидания, чёрный рынок и резерв; субсидии и потолок — отрицательной строкой со штриховкой. Входы раскрываются по цепочке до первого звена (хлеб → мука → зерно), поэтому видно, сколько добавило каждое звено; топливо — сквозная строка «во всех звеньях». Σ частей = цена (тест). Ниже — «что изменилось за месяц» (причины из журнала). Открывается и из сводки месяца кнопкой «Рентген» у цены.
- Графики: ИПЦ, безработица, ИЦП, ставка, ВВП, зарплата, сальдо бюджета, госдолг — по одному показателю на график (без второй оси), курсор с значением, таблица последних 12 месяцев. Минимальный размах оси (±1 пункт индекса, ±1 п.п., доля от среднего для денег), чтобы мелкие колебания не выглядели обвалом. Нажатие на ИПЦ, безработицу или бюджет в верхней панели — «Почему?» вместе с графиком.
- Цвета групп — проверенная категориальная палитра (светлая и тёмная); цвет следует за группой, рядом всегда подпись со значением и долей. Наложение двух прогонов — v0.2.
- Курс валюты на графиках появится вместе с импортом (v0.2).

### Адаптивность
- Mobile portrait (от 360×640) и desktop landscape (1366×768).
- Режим проектора: крупные шрифты, высокий контраст.

### Глоссарий
Любой экономический термин в UI тапается → короткое определение (1–2 предложения) + «где это видно в игре».

## 8. Режимы

| Режим | Описание | Версия |
|---|---|---|
| Кампания | 12 уровней от простого к сложному | MVP: 5 уровней |
| Задачи | короткие сценарии на 10–15 минут | v0.3 |
| Песочница | свободная экономика, все рычаги, свои шоки | MVP: облегчённая |
| Режим учителя | см. ниже | v1.0 (код сценария — MVP) |
| Мультиплеер | — | вне скоупа |

### Режим учителя
- Выбор уровня/сценария, фиксированный seed, ограничение доступных рычагов.
- **Код сценария** (короткая строка + QR): весь класс открывает одно и то же без сервера.
- **Код результата:** в конце ученик получает строку/QR с итогом (звёзды, показатели, ключевые решения), подписанную контрольной суммой. Учитель вставляет коды — видит таблицу класса. Без сервера и без персональных данных.
- Методичка к каждому уровню: цель урока, вопросы для обсуждения, типичные ошибки учеников.

## 10. Методика

- **Сначала действие, потом объяснение.** Брифинг короткий, теория — в отчёте после уровня.
- **«Что если»:** после уровня можно переиграть с точки любого решения, и графики двух прогонов накладываются (ghost run). Это сильнейший обучающий приём: ученик видит альтернативу.
- **Вопросы для обсуждения:** 2–3 на уровень в отчёте и в методичке.
- **Соответствие программе:** привязка уровней к темам школьного курса обществознания/экономики (таблица в методичке). Без претензии на официальную сертификацию.
- **Нейтральность модели:** игра не продвигает одну экономическую школу. Каждый инструмент имеет и плюсы, и издержки.

## 11. Данные (всё в JSON, валидируется схемами)

```
data/
  balance.json        // все константы модели (α, β, ε, λ, ...)
  goods.json          // товары
  recipes.json        // рецепты производства

  shocks.json         // шоки: эффекты, длительность

  glossary.json       // термины
```

Уровень описывает: стартовое состояние, seed, доступные рычаги и здания, скрипт шоков по ходам, цели и условия звёзд, тексты брифинга, вопросы для обсуждения.

## 12. Технологии

**Web, TypeScript.**

| Слой | Выбор | Почему |
|---|---|---|
| Язык | TypeScript (strict) | лучше всего работает с Claude Code, строгая типизация модели |
| Сборка | Vite | быстрая, простая |
| UI | Preact | маленький (~4 KB), React-подобный |
| Карта | PixiJS v8 | быстрая 2D-анимация потоков, WebGL с fallback |
| Графики | uPlot | крошечный и быстрый, тянет слабые ПК |
| Схемы данных | zod | валидация JSON-контента |
| Тесты | Vitest | unit, golden и invariant тесты симуляции |
| Офлайн | vite-plugin-pwa | установка на устройство, работа без сети |
| Деплой | GitHub Pages + GitHub Actions | каждый push сразу играбелен по ссылке, в том числе с телефона |

**Почему не Godot:** web-экспорт тяжёлый (десятки МБ, медленный старт на школьных ПК), а игра на 70% состоит из UI, текста и графиков, что удобнее делать в HTML. Headless-тесты модели в TS проще.

**Почему не Android/Kotlin:** школам нужен браузер без установки на любом устройстве.

## 14. Критерии успеха
- Уровень проходится за ≤ 35 минут.
